# Wheelset bearing support stiffness from multi-pass axle-box acceleration

Code, stored results and LaTeX source for the paper *Tracking the support stiffness of railway wheelset
bearings from multi-speed axle-box acceleration without measuring rail roughness: a multi-pass debiased
Whittle likelihood* (submitted to Mechanical Systems and Signal Processing).

The method pools axle-box acceleration spectra of many passes at different speeds in one debiased
Whittle likelihood, with the rail roughness spectrum levels as nuisance parameters, and identifies the
vertical support stiffness of the wheelset bearing and its change between monitoring periods. All
results are from simulation with a finite-element wheelset coupled to neighbouring wheels through an
infinite Timoshenko rail, for a representative Y25-bogie freight wagon on ballasted 60E1 track.

## What this repository reproduces

Every table, figure and number quoted in the paper. Numbers are LaTeX macros written by
`experiments/make_paper_numbers.py` into `paper/generated/numbers.tex`; tables are written by
`experiments/make_tables.py` into `results/tables/`; figures by `experiments/make_figures.py` into
`figures/`. None is typed by hand. Each of these is read from a JSON result file in `results/`, written
by one experiment script through `src/utils/results.py`, which records the git commit, the hash of the
configuration used, the estimator version, the seed and the run time.

`docs/provenance.md` (written by `experiments/make_provenance_check.py`) lists the result file and the
configuration behind every table, figure and macro, and marks the results that come from an earlier
configuration of the model; `config/provenance.yaml` holds the declarations.

## Requirements

- Python 3.13 with the pinned packages in `requirements.txt` (`pip install -r requirements.txt`).
- For the PDF: TeX Live 2023 with the Elsevier `cas-sc` class, `natbib`, `booktabs`, `lmodern` and
  `cm-super`.
- Rebuilding the paper from the stored results takes minutes on one core. Regenerating the stored
  results takes about 80 core-hours at the frozen configuration (`docs/compute_cost.md`, from the
  wall times recorded in the run files); the scripts run single-threaded and are meant to be run in
  parallel on several cores.

## Commands

```bash
pip install -r requirements.txt
make test          # unit tests of the finite-element, rail and track models
make reproduce     # tables, figures and numbers from results/, then paper/main.pdf and the checks
make check         # provenance, freeze and reference checks, and the MSSP submission folder
make montecarlo    # regenerate results/ from scratch (long; scripts/regenerate_all.sh)
```

`make reproduce` needs no simulation: it reads the stored results. `make montecarlo` reruns every
simulation at the frozen configuration in the order given in `scripts/regenerate_all.sh`; every Monte
Carlo script is resumable and stops itself within two hours, so the commands can be repeated and run in
parallel. Results from an earlier configuration are stored but not regenerated by it (see
`docs/provenance.md`).

## Seeds

Every dataset is generated from a `numpy.random.SeedSequence` key written into its result row. The
headline Monte Carlo uses seeds 42, 123, 456, 789 and 1024 (keys `(seed, SNR, j)`); the other studies use
fixed study keys documented in each script's docstring (for example `(49, j, period)` for the
payload-band pairs and `(60, j)` for the nonlinear-contact datasets).

## Layout

```
config/            vehicle, bearing and track parameters with sources (params.yaml, track.yaml);
                   snapshots/ for pinned configurations; provenance.yaml
src/reference/     finite-element wheelset, rail and track models, time-domain contact generator
src/analysis/      bound and multi-wheel model assembly
src/inverse/       multi-pass debiased Whittle likelihood (multipass.py), roughness model (whittle.py)
src/utils/         results.py: the single writer of results/ (provenance, config hash, estimator version)
experiments/       one script per study (p1_* to p4_*) and the generators of tables, figures and numbers
scripts/           regenerate_all.sh
results/           JSON and JSONL written by scripts, never edited by hand
figures/           figure PDFs and their source manifest
paper/             LaTeX source; paper/submission/ for the MSSP submission folder
docs/              parameter sources, literature notes, reference and provenance checks, release checklist
tests/             unit tests
legacy/            exploratory code from an earlier phase (S²-PINN surrogate, gPC); not part of the paper
```
